# aubreys-automation

Source of truth for Aubrey's Inc. automation: Data Factory, domesday SQL, Azure Functions and the web pieces they feed. One domain at a time, built side by side with what it replaces.

| Folder | What |
|---|---|
| `adf/dmcp-data-factory/` | ADF native git folder for `dmcp-data-factory` (generated by `tools/build_adf.py`) |
| `sql/domesday/` | DDL and procedures for `mcp-alex/domesday`, run in numeric order; all re-runnable |
| `functions/ig-etl/` | `aub-ig-etl` Azure Function: InfoGenesis export parsers (managed identity, no keys) |
| `web/menu-lib/` | Shared PHP bar-menu library (Bluehost, outside `public_html`) |
| `web/store-bar-folder/` | The few shim files that go in each store's `menu/bar/` folder |
| `contracts/` | JSON schemas for files other systems read |
| `docs/domains/` | One page per domain: what runs, when, as whom, from where to where |
| `docs/runbooks/` | Setup and cutover steps |
| `docs/ig/` | Standards for the IG sysadmin |
| `tools/` | Generators and offline previews |
| `samples/` | Menu JSON and exception lists built from the 2026-10-16 exports for stores 02 and 12 |

Domains: [menus](docs/domains/menus.md)

## Conventions

- Everything new uses managed identity: no account keys, SAS tokens or SQL logins.
- Every pipeline logs to `ops.pipeline_run` / `ops.run_event` and notifies through `pl_ops_notify`. A new domain needs a row in `ops.domain` and, if it expects files, rows in `ops.feed_expectation`.
- Alerts route by area (`ops.area`): Slack `#alert-<area>-automation`, email to the area's mail-enabled security group, sent from `automation@aubreys.group`.
- No in-place edits to live flows; build side by side, cut over one store or one domain at a time, never on a Friday.
